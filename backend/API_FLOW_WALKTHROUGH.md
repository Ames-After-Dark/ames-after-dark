## Layer 1: Presentation (Controllers)

**File**: `src/controllers/DDD-LocationController.js`
**Responsibility**: Parse HTTP request, call application service, format response

```javascript
class DDD_LocationController {
  async createLocation(req, res) {
    try {
      // 1️⃣ Extract data from HTTP request
      const { name, latitude, longitude, address } = req.body;
      
      // 2️⃣ Create DTO (Data Transfer Object)
      const dto = new CreateLocationDTO(name, latitude, longitude, address);
      
      // 3️⃣ Validate input through DTO
      dto.validate();
      // ↑ Throws error if invalid: missing fields, bad coordinates, etc.
      
      // 4️⃣ Get application service from DI container
      const locationService = getServiceContainer().getLocationApplicationService();
      
      // 5️⃣ Call application service
      const result = await locationService.createLocation(dto);
      // ↑ Service handles the use case
      
      // 6️⃣ Format and respond with DTO
      res.status(201).json(result);
      
    } catch (err) {
      // Error handling: Bad request (400), Not found (404), etc.
      if (err.message.includes('required') || err.message.includes('invalid')) {
        res.status(400).json({ message: err.message });
      } else {
        res.status(500).json({ message: 'Internal server error' });
      }
    }
  }
}
```

**Key Points**:
- ✅ Doesn't touch database directly
- ✅ Doesn't execute business logic
- ✅ Only orchestrates HTTP ↔ application service

**What's dispatched to the next layer**: 
```javascript
{
  name: "The Irish Pub",
  latitude: 42.3601,
  longitude: -93.6401,
  address: "123 Main St"
}
// Wrapped in CreateLocationDTO
// Which then gets passed to ApplicationService
```

## Layer 2: Application (Services + DTOs)

**File**: `src/application/services/LocationApplicationService.js`
**Responsibility**: Orchestrate use cases, coordinate repositories, publish events

```javascript
class LocationApplicationService {
  constructor(locationRepository, eventPublisher) {
    this.locationRepository = locationRepository;      // Infrastructure layer
    this.eventPublisher = eventPublisher;              // Infrastructure layer
  }

  async createLocation(dto) {
    // 1️⃣ Validate DTO (format validation)
    dto.validate();
    // ↑ Throws if: name is empty, coordinates out of bounds, etc.
    
    // 2️⃣ Extract validated data
    // ↓ Now we know data is in correct format
    
    // 3️⃣ CREATE AGGREGATE - Pass to domain layer
    const location = Location.create(
      null,                                    // ID will be generated by DB
      dto.name,                               // From DTO
      new Coordinates(dto.latitude, dto.longitude),  // ← Value Object!
      {
        address: dto.address
      }
    );
    // ↑ Aggregate created with business logic
    // ↑ Domain events published (LocationCreatedEvent)
    
    // 4️⃣ PERSIST AGGREGATE - Pass to infrastructure
    const saved = await this.locationRepository.save(location);
    // ↓ Repository handles database interactions
    // ↓ Returns updated aggregate with ID
    
    // 5️⃣ PUBLISH DOMAIN EVENTS - Event infrastructure
    saved.getUncommittedEvents().forEach(event => {
      this.eventPublisher.publish(event);
    });
    // ↑ Published: LocationCreatedEvent
    // ↑ Subscribers can respond (analytics, emails, etc.)
    
    // 6️⃣ CONVERT TO DTO - Back to presentation layer
    return LocationResponseDTO.fromDomain(saved);
    // ↑ Clean, safe data for HTTP response
  }
}
```

**DTO Purpose** (Important!):

```javascript
// Input DTO: Validates and structures incoming data
class CreateLocationDTO {
  constructor(name, latitude, longitude, address) {
    this.name = name;
    this.latitude = latitude;
    this.longitude = longitude;
    this.address = address;
  }

  validate() {
    if (!this.name || this.name.trim() === '') {
      throw new Error('Location name is required');
    }
    if (!Number.isFinite(this.latitude) || this.latitude < -90 || this.latitude > 90) {
      throw new Error('Invalid latitude');
    }
    if (!Number.isFinite(this.longitude) || this.longitude < -180 || this.longitude > 180) {
      throw new Error('Invalid longitude');
    }
    // ↑ Format validation - is the data in legal format?
  }
}

// Output DTO: Clean data sent back to client
class LocationResponseDTO {
  static fromDomain(location) {
    return {
      id: location.id,
      name: location.name,
      latitude: location.coordinates.latitude,  // Not exposed raw
      longitude: location.coordinates.longitude, // Properly structured
      address: location.address,
      views: location.views,
      isOpen: location.isOpen,
      createdAt: location.createdAt
      // ↑ No sensitive fields leaked
      // ↑ Only what client should see
    };
  }
}
```

**Key Points**:
- ✅ Orchestrates use cases (business processes)
- ✅ Uses repositories (doesn't know they use Prisma)
- ✅ Publishes domain events
- ✅ Returns DTOs for HTTP response

```

// Creates aggregate that goes to repository
```

## Layer 3: Domain (Business Logic)

**File**: `src/domain/entities/Location.js`
**Responsibility**: Implement business rules, manage state, publish events

```javascript
class Location extends AggregateRoot {
  constructor(id, name, coordinates, props = {}) {
    super(id);  // ← Extends AggregateRoot to manage events
    
    // Business state
    this.name = name;
    this.coordinates = coordinates;        // ← Value Object!
    this.address = props.address;
    this.views = props.views ?? 0;
    this.isOpen = props.isOpen ?? false;
    this.createdAt = props.createdAt ?? new Date();
    this.updatedAt = props.updatedAt ?? new Date();
  }

  // 🎯 FACTORY METHOD - Creates new aggregate
  static create(id, name, coordinates, props = {}) {
    // 1️⃣ Create instance
    const location = new Location(id, name, coordinates, props);
    
    // 2️⃣ Publish DOMAIN EVENT
    location.publishEvent(
      new LocationCreatedEvent(location.id, name, coordinates)
    );
    // ↑ Anyone listening can react to this event
    // ↑ Example: Send analytics, welcome email, update user stats
    
    // 3️⃣ Return new aggregate
    return location;
  }

  // 🎯 BUSINESS LOGIC - Record a view
  recordView() {
    // Business rule: Increment views, publish event
    this.views += 1;
    this.publishEvent(new LocationViewedEvent(this.id));
    // ↑ Event can trigger: notifications, streaks, achievements
  }

  // 🎯 BUSINESS LOGIC - Check distance
  isNear(otherCoordinates) {
    // Business rule: Haversine formula for distance
    const distance = this.coordinates.distanceTo(otherCoordinates); // ← Value Object method!
    return distance < 1; // Within 1 km
  }

  // 🎯 BUSINESS LOGIC - Open/Close location
  markAsOpen() {
    this.isOpen = true;
    this.publishEvent(new LocationOpenedEvent(this.id));
  }

  markAsClosed() {
    this.isOpen = false;
    this.publishEvent(new LocationClosedEvent(this.id));
  }

  // Convert to plain object (for serialization)
  toObject() {
    return {
      id: this.id,
      name: this.name,
      latitude: this.coordinates.latitude,
      longitude: this.coordinates.longitude,
      address: this.address,
      views: this.views,
      isOpen: this.isOpen,
      createdAt: this.createdAt,
      updatedAt: this.updatedAt
    };
  }
}
```

**Value Object** (Used by aggregate):

```javascript
// File: src/domain/value-objects/Coordinates.js
class Coordinates extends BaseValueObject {
  constructor(latitude, longitude) {
    super();
    
    // Validation - encapsulated here, not scattered
    if (latitude < -90 || latitude > 90) {
      throw new Error('Latitude must be between -90 and 90');
    }
    if (longitude < -180 || longitude > 180) {
      throw new Error('Longitude must be between -180 and 180');
    }
    
    this.latitude = latitude;
    this.longitude = longitude;
  }

  // Business logic specific to coordinates
  distanceTo(other) {
    // Haversine formula - calculate distance between two points
    const R = 6371; // Earth radius in km
    const dLat = (other.latitude - this.latitude) * Math.PI / 180;
    const dLon = (other.longitude - this.longitude) * Math.PI / 180;
    const a = 
      Math.sin(dLat / 2) * Math.sin(dLat / 2) +
      Math.cos(this.latitude * Math.PI / 180) * Math.cos(other.latitude * Math.PI / 180) *
      Math.sin(dLon / 2) * Math.sin(dLon / 2);
    const c = 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1 - a));
    return R * c;
  }

  // Value object equality (not identity)
  getEqualityComponents() {
    return [this.latitude, this.longitude];
  }
}
```

## Layer 4: Infrastructure (Persistence)

**File**: `src/infrastructure/repositories/PrismaLocationRepository.js`
**Responsibility**: Map aggregate ↔ database, execute queries

```javascript
class PrismaLocationRepository extends ILocationRepository {
  // Constructor receives Prisma client
  constructor(prisma = require('../../db')) {
    this.prisma = prisma;
  }

  // SAVE: Aggregate → Database
  async save(location) {
    // 1️⃣ Convert aggregate to database format
    const data = this.toPersistence(location);
    
    // 2️⃣ Check if exists (update) or new (create)
    const exists = await this.findById(location.id);
    
    let raw;
    if (exists) {
      // Update existing
      raw = await this.prisma.locations.update({
        where: { id: location.id },
        data // ← Converted data
      });
    } else {
      // Create new
      raw = await this.prisma.locations.create({
        data // ← Converted data
      });
    }
    
    // 3️⃣ Convert back to aggregate
    return this.toDomain(raw);
    // ↑ Returns aggregate with ID from database
  }

  // FIND: Database → Aggregate
  async findById(id) {
    // 1️⃣ Query database
    const raw = await this.prisma.locations.findUnique({
      where: { id }
    });
    
    // 2️⃣ If not found, return null
    if (!raw) return null;
    
    // 3️⃣ Convert to aggregate
    return this.toDomain(raw);
    // ↑ Returns Location aggregate, not raw data
  }

  // MAPPING: Aggregate → Database Format
  toPersistence(domain) {
    const obj = domain.toObject();
    return {
      // Database column names (snake_case)
      name: obj.name,
      latitude: obj.coordinates.latitude,    // Extract from Value Object
      longitude: obj.coordinates.longitude,  // Extract from Value Object
      address: obj.address,
      views: obj.views,
      is_open: obj.isOpen,  // Translate property names
      updated_at: new Date()
    };
  }

  // MAPPING: Database Format → Aggregate
  toDomain(raw) {
    // Create Value Object from database fields
    const coordinates = new Coordinates(
      raw.latitude,
      raw.longitude
    );

    // Create aggregate instance
    return new Location(
      raw.id,
      raw.name,
      coordinates,
      {
        address: raw.address,
        views: raw.views,
        isOpen: raw.is_open,
        createdAt: raw.created_at,
        updatedAt: raw.updated_at
      }
    );
  }
}
```

## Layer 5: Shared (Base Classes)

**Files**: `src/shared/`
**Responsibility**: Provide base classes, cross-cutting concerns

```javascript
// BaseEntity - Base for all domain objects
class BaseEntity {
  constructor(id) {
    this.id = id;
  }

  // Entities have IDENTITY-based equality
  equals(other) {
    return this.id === other.id;
  }
}

// AggregateRoot - Manages domain events
class AggregateRoot extends BaseEntity {
  constructor(id) {
    super(id);
    this.uncommittedEvents = []; // Queued events
  }

  publishEvent(event) {
    this.uncommittedEvents.push(event);
  }

  getUncommittedEvents() {
    return this.uncommittedEvents;
  }

  clearUncommittedEvents() {
    this.uncommittedEvents = [];
  }
}

// DomainEvent - Base for all events
class DomainEvent {
  constructor(eventType) {
    this.eventType = eventType;
    this.occurredAt = new Date();
  }
}

// EventPublisher - Publish events (in-memory, could be RabbitMQ)
class EventPublisher {
  constructor() {
    this.subscribers = {}; // { 'EventType': [handler1, handler2] }
  }

  subscribe(eventType, handler) {
    if (!this.subscribers[eventType]) {
      this.subscribers[eventType] = [];
    }
    this.subscribers[eventType].push(handler);
  }

  publish(event) {
    const handlers = this.subscribers[event.eventType] || [];
    handlers.forEach(handler => handler(event));
  }
}
```

**Key Points**:
- ✅ Shared by all layers
- ✅ No domain-specific logic
- ✅ Defines patterns everyone follows

## Complete Flow Summary

```
1️⃣ HTTP Request
   POST /api/locations
   { "name": "Irish Pub", "latitude": 42.3601, "longitude": -93.6401 }
   
   ↓
   
2️⃣ Controller (Layer 1)
   - Parse request
   - Create CreateLocationDTO
   - Validate DTO
   - Call LocationApplicationService
   
   ↓
   
3️⃣ Application Service (Layer 2)
   - Validate DTO format
   - Call Location.create()
   - Call repository.save()
   - Publish events
   - Return LocationResponseDTO
   
   ↓
   
4️⃣ Domain - Location Aggregate (Layer 3)
   - Create instance
   - Publish LocationCreatedEvent
   - Return aggregate
   
   ↓
   
5️⃣ Repository (Layer 4)
   - Convert aggregate to DB format
   - INSERT into database
   - Convert raw data back to aggregate
   - Return aggregate with ID
   
   ↓
   
6️⃣ Event Publisher (Layer 4)
   - Take LocationCreatedEvent
   - Call any subscribers
   
   ↓
   
7️⃣ HTTP Response (Layer 1)
   201 Created
   {
     "id": 1,
     "name": "Irish Pub",
     "latitude": 42.3601,
     "longitude": -93.6401,
     "views": 0,
     "isOpen": false,
     "createdAt": "2024-01-15T10:30:00Z"
   }
```

## Key Insights

### 1. Separation of Concerns
- Controllers: Only HTTP
- Services: Only orchestration
- Aggregates: Only business logic
- Repositories: Only persistence
- Shared: Only base patterns

### 2. Data Transformation
```
HTTP Request 
  → DTO (validates)
  → Domain (encapsulates logic)
  → Repository (maps)
  → Database
  → Repository (maps back)
  → Domain (returns aggregate)
  → DTO (clean)
  → HTTP Response
```

### 3. Unidirectional Dependencies
```
Controllers
    ↓
Application Services
    ↓
Repositories & Domain
    ↓
Database
```
Never flow UP the chain.

### 4. Single Responsibility
Each layer does ONE thing:
- Controllers: Parse HTTP
- Services: Orchestrate
- Domain: Business logic
- Repositories: Persistence
- Shared: Base patterns

### 5. Testability
- **Domain** (Unit tests): Test Location without repository
- **Application** (Integration tests): Test service with mock repository
- **API** (E2E tests): Test HTTP endpoints with real server


## Real Example: Adding a Feature

### Feature: "What if we want to track location visits by user?"

**Old Way** (Scattered, hard to maintain):
```javascript
// In controller
router.post('/locations/:id/visit', async (req, res) => {
  const { userId } = req.body;
  await prisma.locations.update({ where: { id }, data: { views: { increment: 1 } } });
  await prisma.userVisits.create({ data: { userId, locationId: id } });
  res.json({ success: true });
});
```

**DDD Way** (Clean, reusable, testable):
```javascript
// 1. Add to aggregate
class Location extends AggregateRoot {
  recordUserVisit(userId) {
    this.visits.push({ userId, timestamp: new Date() });
    this.publishEvent(new UserVisitedLocationEvent(this.id, userId));
  }
}

// 2. Add to application service
async recordLocationVisit(locationId, userId) {
  const location = await this.locationRepository.findById(locationId);
  location.recordUserVisit(userId);
  const saved = await this.locationRepository.save(location);
  this.eventPublisher.publish(saved.getUncommittedEvents());
  return LocationResponseDTO.fromDomain(saved);
}

// 3. Add to controller
async recordVisit(req, res) {
  const { locationId } = req.params;
  const { userId } = req.body;
  const result = await this.locationService.recordLocationVisit(locationId, userId);
  res.json(result);
}

// 4. Add event subscriber
eventPublisher.subscribe('UserVisitedLocationEvent', (event) => {
  // Update user stats, send notification, track analytics, etc.
  console.log(`User ${event.userId} visited location ${event.locationId}`);
});
```

**Advantages**:
- ✅ Business logic (recordUserVisit) in aggregate
- ✅ Reusable from web or CLI
- ✅ Event can trigger other features
- ✅ Easy to test each layer independently
- ✅ Changes are localized to one area

## Conclusion

This is DDD:
- Business logic in aggregates (domain)
- Orchestration in services (application)
- Persistence abstracted by repositories (infrastructure)
- HTTP handling in controllers (presentation)
- Reusable patterns in shared (shared)

Each layer has ONE job. Each request flows through all 5 layers. New domains follow the same pattern.

That's the pattern you'll repeat for Event, Deal, Friendship, and every other domain.
